# Две сборки, один интерфейс

## Открытый potok
Основное место разработки. Экспортирует исходники `@potok/core`: App, общие компоненты, hooks, модели и стили. `src/Site.jsx` открывает локальное личное расписание. `src-tauri` — начальная системная оболочка, не копия интерфейса. Сборка для браузера остаётся доступна для разработки и проверок; самостоятельный публичный сайт здесь не публикуется.

## Закрытый potok-cloud
Содержит лендинг, веб-маршруты, настройки нашего Firebase, Hosting, функции напоминаний и автопубликацию. Общий код подключается как локальный пакет `file:vendor/potok`, не копируется в src. Версия фиксируется полным SHA в core-source.json. Для совместной локальной разработки vendor/potok может быть символьной ссылкой на этот checkout; скрипт обновления отказывается перезаписывать такую ссылку.

## Настройки и доверие
Открытый клиент по умолчанию локальный. Авторизация, хранилище, настройки подключения и уведомления передаются через явный провайдер; `App` и `useWorkspace` не импортируют Firebase. Необязательный Firebase-адаптер лежит в `src/adapters/firebase`, SDK — optional peer dependency ядра. Закрытый сайт выбирает этот адаптер в собственном `src/cloud-provider.js` и получает конфигурацию из VITE_FIREBASE_CONFIG. Идентификаторы Firebase в браузерной сборке публичны по определению; права обеспечивают серверные правила, авторизация и IAM. Административные ключи не хранятся ни в одном git-репозитории.

После push в main открытый workflow сначала выполняет verify. Затем отдельный notify_cloud без checkout исходников вызывает workflow_dispatch закрытого deploy.yml с точным проверенным SHA. Для вызова используется Actions secret POTOK_CLOUD_DISPATCH_TOKEN: fine-grained токен с Actions read/write только для potok-cloud, без права изменения исходников. Pull request и другие ветки не запускают публикацию. Токен с ограниченным сроком нужно обновить до истечения.

Закрытый workflow проверяет и собирает этот SHA и публикует сайт через свою Google OIDC identity. Новая версия записывается в core-source.json только после успешной публикации. При неудаче запуск можно повторить из Actions; периодический опрос больше не является механизмом обновления. Ручной workflow_dispatch позволяет опубликовать конкретный SHA. JSON фиксирует версию, а не запускает workflow.

## Разработка и следующие этапы
Интерфейс проверяется в браузере. Для системных возможностей нужен desktop-запуск и платформенные инструменты Tauri. Текущая локальная база остаётся localStorage; SQLite, устойчивую офлайн-очередь и системный Google OAuth добавляем отдельными изменениями. Установщики открытого приложения публикуются по тегу отдельным `desktop-release.yml`; конфигурация Firebase владельца проекта в них не включается. Разделение не меняет формат расписания и существующие данные пользователей.

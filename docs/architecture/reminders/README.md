# Напоминания о переносе

Одно разовое напоминание для конкретного pending-события. «Завтра» — следующий московский день, 09:00; произвольный момент выбирается двумя постоянно видимыми полями даты и времени с подписью МСК. На телефоне время открывает общий TimeInput с прокручиваемыми колонками часов и минут. Хранится UTC ISO. Прошлые/несуществующие даты и даты дальше года отклоняются. Изменение времени создаёт новый id доставки. После назначения даты, проведения, отмены или удаления события напоминание удаляется при нормализации перед сохранением.

В очереди ожидающих событий есть отдельная кнопка «Напомнить», открывающая отдельный ReminderDialog только с датой и временем. Нажатие на название открывает полную EventDetails. «Выбрать дату» отдельно открывает перенос; эта операция не должна перехватывать доступ к напоминанию.

## Файлы
- `src/components/EventReminder.jsx` — общий редактор даты и времени, быстрые варианты и ошибки. `ReminderDialog.jsx` открывает только настройку напоминания из очереди, без статуса, полей и действий события.
- `src/lib/reminders.js` — проверка времени, сохранение/удаление, форматирование.
- `src/lib/reminder-model.js` — общие фильтры актуальности, индекс следующего времени, персональный текст.
- `src/App.jsx` — наступившие напоминания внутри приложения и переход к конкретному событию из push. Проверка раз в минуту и при возврате во вкладку.
- `src/lib/push-notifications.js` — разрешение по нажатию, ленивый SDK, регистрация устройства и отзыв при выходе. При смене аккаунта старый FCM-токен аннулируется перед регистрацией нового.
- `public/firebase-messaging-sw.js` — системное уведомление и переход `/app?event=…&uid=…`. Другой аккаунт не открывает карточку из ссылки.
- `functions/index.js` — Cloud Scheduler раз в минуту, FCM, аренда доставки и журнал результатов на устройство.

## Хранение
`payload.reminders`: `{id,eventId,at,timeZone}[]`, до 200 активных. Облачный индекс `nextReminderAt` добавляется только при включённой push-конфигурации: обычные сохранения совместимы со старыми опубликованными правилами. Сервер меняет только индекс, не payload/revision редактирования.

`users/{uid}/pushDevices/{sha256(token)}`: token и server updatedAt, доступны владельцу. `users/{uid}/reminderDeliveries/{reminderId}`: только сервер. Проверка текущего pending-события повторяется перед отправкой. Успешные устройства не отправляются повторно, недействительные токены удаляются, временные ошибки повторяются следующими проходами. Аренда на 2 минуты защищает от параллельных запусков. Редкий сбой между отправкой и записью может вызвать повтор; одинаковый notification tag заменяет уведомление. Доставки старше суток прекращаются. Лимиты: 50 расписаний за запуск, 20 устройств на аккаунт. Доставка не гарантируется в точную секунду.

## Текущее состояние
Выбор, сохранение, изменение, удаление и напоминания внутри открытого приложения работают. Push выключен: `VITE_EVENT_PUSH_ENABLED=false`; разрешение само не запрашивается. Реальная доставка FCM после закрытия сайта ещё не проверена и требует настройки проекта.

## Подключение push
1. Проверить/подключить Firebase Blaze для Cloud Functions и Scheduler. Это меняет биллинг; автоматически не включать.
2. Firebase → Project settings → Cloud Messaging → Web Push certificates → Generate key pair. Публичный ключ положить в `VITE_FIREBASE_VAPID_KEY`. Включить FCM API, если выключен.
3. `npm ci --prefix functions`, затем опубликовать `functions:reminders`, `firestore:rules`, `firestore:indexes` через Firebase CLI. Текущий CI аккаунт имеет только Hosting-права; автоматически их не расширять.
4. После успешной публикации поставить `VITE_EVENT_PUSH_ENABLED=true`, пересобрать и опубликовать Hosting. Сохранить расписание, чтобы появился delivery index для существующих напоминаний.
5. На устройстве нажать «Включить уведомления», разрешить их и проверить тестовое событие при закрытой вкладке. На iPhone открыть установленное на домашний экран веб-приложение. Название события будет видно в уведомлении на устройстве.

Документация: https://firebase.google.com/docs/cloud-messaging/web/get-started и https://firebase.google.com/docs/functions/schedule-functions

Проверки: `tests/reminders.test.js`, `tests/event-reminder.test.jsx`, `tests/rules/workspace.rules.test.js`. Живая доставка отдельно проверяется после настройки и публикации.

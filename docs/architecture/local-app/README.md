# Устанавливаемое приложение: варианты

Статус: предложение, не реализовано. Интерфейс Preact/Vite можно сохранить.

## Что есть сейчас
`src/lib/storage.js` сохраняет локальный режим в localStorage. `src/lib/firebase-client.js` включает persistentLocalCache в IndexedDB и кеш нескольких вкладок. Облачная запись использует runTransaction с проверкой revision: она требует сети. Кеш не означает, что облачное расписание уже можно редактировать офлайн.

## Варианты оболочки
- PWA: установка с сайта, отдельное окно и значок. Нужны manifest и кеш оболочки через service worker; данные — IndexedDB. Самый короткий путь, но хранением управляет браузер. Установка сама по себе не реализует офлайн.
- Tauri 2 + SQLite: устанавливаемое приложение с локальной базой в каталоге приложения. Сохраняет текущий UI; системное WebView вместо собственного Chromium. Нужны сборка/обновления, браузерный Google OAuth с возвратом в приложение и проверка карт в WebView.
- SwiftUI + SwiftData/SQLite: отдельный интерфейс для Apple, больше нативных возможностей. Существенно больше новой реализации и отдельный путь для других платформ.

Рекомендация для цели «установил, данные на компьютере»: Tauri + SQLite. Firebase можно сохранить для Google-входа и сетевой синхронизации.

## Синхронизация
Оболочка и синхронизация — независимые решения. Между компьютером и телефоном вне одной сети использовать существующий Firebase. Локальная сеть — дополнительный транспорт: нужны обнаружение устройств, защищённое сопряжение и одновременная доступность обоих устройств. Общий Wi-Fi сам ничего не синхронизирует.

Перед офлайн-записью отделить локальное хранилище от App/useWorkspace: интерфейс читает локальную базу, изменения атомарно пишутся вместе с очередью операций. Каждая операция имеет устойчивый ID и версию объекта; повторная отправка не создаёт дублей. События, записи и шаблоны синхронизируются отдельно, удаления передаются как tombstones. Параллельные изменения одного объекта требуют разрешения конфликтов; проверки пересечений после синхронизации не должны молча отменять локальную работу. Нельзя просто заменить transaction полной перезаписью: расписание сейчас хранится одним документом, что приведёт к потерям при параллельном офлайн-редактировании.

Фоновые напоминания при закрытом приложении — отдельная задача; PWA/Tauri сами её не решают.

# История и переносы

`JournalView.jsx` объединяет обе очереди и архив. Сверху показаны все прошедшие события, которые ждут подтверждения, от новых к старым, и отдельная очередь без даты. Месяц и фильтры относятся к архиву событий. `unconfirmedEvents` включает прошедшие повторы, подставляет сохранённые экземпляры по ID и исключает проведённые, отменённые и ожидающие новой даты события. `eventState` вычисляет «Ждёт подтверждения» по времени окончания в МСК. `EVENT_STATES` задаёт единые подписи, иконки и действия. Эффекты календаря и запись о переносе относятся к оформлению и истории встречи.

`HistoryView.jsx` проецирует `historyEvents` за выбранный месяц, фильтрует статус и запрос. Список показывает компактные строки вместо развёрнутых календарных карточек: время, название, контекст, подтверждение проведения. Нажатие передаёт в инспектор сам исторический occurrence, а отметка проведения — тот же объект и новый статус. Это сохраняет правильную обработку повторов. Оранжевое закрашивание остаётся в календаре, в истории оно не используется.

`TransferQueue` показывает встречи без даты. `TransferHistory` показывает последнее изменение даты или времени и текущий статус встречи. Сортировка использует последнюю запись history. Открытие передаёт ID сохранённого события в App.

Журнал использует `EventListRow`, а ожидание — `PendingEventCard`. Оформление принадлежит `activity-views.css`, цвета — семантическим переменным `theme/colors.css`. Ссылки формирует общий `lib/links.js:eventLinks`: собственная ссылка события имеет приоритет над общей ссылкой записи с тем же адресом или названием поля. Отображаемые поля выбирает вызывающий компонент. Очередь событий без даты также доступна в левой колонке [доски задач](../board/README.md).

Проверки: `tests/activity-views.test.jsx`, `tests/links-history.test.jsx`. Для проверки заполненных экранов в браузере — `/tests/ui/` на локальном сервере.

## Статистика

`StatisticsView.jsx` задаёт период, независимые фильтры по записи и типу, условия по полям, показатель и разбивку. `statistics.js` готовит строки отчёта из сохранённых экземпляров со статусом «Проведено». Используется фактическая дата события и его сохранённые значения. Для удалённых записей остаётся имя из снимка события.

Числовые поля различаются по шаблону, ID поля, формату и единице. Поля можно объединить в показатель, если их единицы совпадают. Нули входят в расчёт, пустые значения считаются отдельно. Группы по полю с несколькими вариантами могут пересекаться. Общий итог считается до группировки. Список и карта используют одну выборку, а выбранная группа ограничивает оба представления.

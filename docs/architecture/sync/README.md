# Авторизация, хранение и синхронизация

## Ответственность
`src/Site.jsx` starts local personal data; the private hosted Site owns the landing and authenticated /app route. Firebase setup is optional in the portable distribution.

`src/hooks/useWorkspace.js` связывает авторизацию, выбранное хранилище, локальную копию и состояние синхронизации. `src/lib/firebase-client.js` создаёт SDK-соединение, подписки и транзакции Firestore. `account-session.js` сохраняет восстановленную сессию между монтированиями; `cloud-workspace.js` читает/проверяет документ и подготавливает новую версию для транзакции. `storage.js` обслуживает локальные данные и экспорт.

## Инварианты
- Правило доступа к данным принадлежит `firestore.rules`, а не наличию/отсутствию кнопки в интерфейсе.
- Сохранение подтверждается после ответа, версия проверяется для обнаружения конфликтов.
- Во время редактирования новые данные помечаются как устаревшая локальная версия и не заменяют черновик.
- Ответ незавершённого сохранения не применяется к другому аккаунту.
- Кэш можно показывать сразу, но запись недоступна до готовности соединения; офлайн доступен просмотр.

Настройки внешнего вида хранятся на устройстве отдельно и не меняют расписание. Firebase Hosting and production deployment are owned by the private distribution.
Проверки: `tests/workspace.test.jsx`, `tests/entry.test.jsx`, `tests/rules/`.

## Ручная и автоматическая проверка
`SyncStatus.jsx` в верхней панели показывает значок обновления и последнее успешное время (МСК). `useWorkspace.sync()` вызывает `account-session.fetch()` → `getDocFromServer`, не пересоздавая приложение/авторизацию. Повторные нажатия делят один запрос; во время записи и без сети проверка не запускается. Успех поступает через общий подписочный канал; при открытом редакторе новая ревизия помечается stale и не заменяет черновик.

Автопроверка — focus, возврат видимости и online, если последняя подтверждённая синхронизация старше 30 секунд. Постоянный Firestore listener продолжает получать изменения других устройств. Последний успех обновляется только при серверном snapshot без pending writes, подтверждении записи или успешном fetch. Cache/offline/error время не сдвигают. Метка сохраняется в необязательном локальном кеше отдельно по uid; ошибка этого кеша не превращает успешную запись в неуспешную. Запросы прежнего аккаунта игнорируются, в том числе при A → B → A. Проверки: `tests/account-session.test.js`, `tests/workspace.test.jsx`.

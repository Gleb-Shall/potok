# Авторизация, хранение и синхронизация

## Граница ядра

`src/Site.jsx` открывает локальные личные данные без аккаунта. `App` принимает необязательный `provider`; закрытый сайт передаёт свой экземпляр из собственного `cloud-provider.js`. Ядро не выбирает сервис по переменной окружения и не импортирует SDK Firebase. Пользовательская авторизация и backend реализуются независимо за общим интерфейсом.

`src/lib/workspace-provider.js` содержит `createWorkspaceProvider`, общий `WorkspaceConflictError`. `auth` отвечает за аккаунт и вход, `storage` — за чтение, подписку и атомарную запись. Нормализованный пользователь имеет `id`, displayName/email/photoURL; SDK-объекты и токены не передаются в UI. [Полный контракт и пример](ADAPTERS.md).

`account-session.js` кеширует аккаунт и данные между монтированиями, отбрасывает старые ревизии и ответы другой сессии, управляет подписками. Провайдер живёт на уровне приложения; `dispose()` явно освобождает его при окончательном отключении. `useWorkspace.js` выбирает локальный/облачный режим и связывает сессию с редактором и состоянием синхронизации. `storage.js` хранит локальные данные и экспорт.

## Сохранение на устройстве и отправка в облако

- После первого входа и загрузки расписания `offline-workspace.js` хранит в localStorage последнюю облачную копию и несинхронизированные изменения. Ключ включает область провайдера и идентификатор аккаунта. Приложение читает копию после восстановления входа через адаптер. Смена аккаунта скрывает данные предыдущего.
- Любое изменение через `App.commit` сначала записывается на устройство. Редактор закрывается после локального сохранения. Ревизия видимых данных защищает от сохранения устаревшего черновика, в том числе из другой вкладки. При наличии Web Locks чтение и обновление копии выполняются под общей блокировкой вкладок.
- Синхронизация читает свежую облачную ревизию и сопоставляет её с исходной и локальной копиями. Независимые правки объединяются по идентификаторам событий, записей, шаблонов и других сущностей. Если изменился один объект с обеих сторон, пользователь выбирает версию для спорных объектов. При удалении или архивировании общего источника приложение предлагает выбрать копию расписания целиком. Если после объединения занятые события пересекаются, можно изменить время локального события или выбрать копию расписания.
- Отправка использует серверный `compareAndSwap`. Отсутствие сети, смена аккаунта или несовпадение серверной ревизии сохраняют очередь на устройстве. Правки, внесённые во время отправки, остаются в очереди. После успешной отправки и подтверждения база для следующих изменений обновляется.
- При доступной сети очередь отправляется автоматически. После сбоя с ожидающими правками выполняется повторная попытка. Доступна ручная синхронизация. Время на кнопке относится к последней успешной связи с сервером.
- Установленная сборка содержит интерфейс. Для офлайн-работы нужна ранее загруженная копия и сохранённая сессия. Первый вход, карты и облачные push-уведомления требуют подключения.

Локальный режим без провайдера использует `storage.js`. Формат расписания и JSON-резервных копий сохранён.

## Необязательный Firebase

`src/adapters/firebase/index.js` переводит Google Auth/Firestore в общий контракт. `config.js` хранит/валидирует клиентские идентификаторы; `workspace.js` читает payload и проверяет ревизии для транзакции; `notifications.js` обслуживает push через текущий Firebase App. Имя App `[DEFAULT]`, путь документа и ключи кеша сохранены, чтобы обновление не сбрасывало вход и данные. Старые `lib/firebase-client.js`, `cloud-config.js`, `cloud-workspace.js`, `push-notifications.js` — переходные пути импорта, ядро их не использует.

Правила доступа принадлежат Firestore Rules, а не кнопкам интерфейса. Открытый локальный dist не содержит Firebase SDK; закрытая сборка устанавливает SDK напрямую и передаёт адаптер явно. [Подключение своего Firebase](SELF_HOSTING.md).

## Ручная и автоматическая проверка

`SyncStatus.jsx` показывает последнюю успешную синхронизацию и вызывает `useWorkspace.sync()` → `connection.fetch()` без пересоздания аккаунта. Повторные нажатия делят запрос; без сети и во время сохранения проверка не запускается. При открытом редакторе свежая ревизия отмечается stale и не перезаписывает черновик.

Focus, online и возврат видимости запускают проверку, если последний подтверждённый ответ старше 30 секунд. Подписка адаптера может доставлять изменения непрерывно. Только серверный snapshot, успешный read или подтверждённая запись обновляют время. Ошибки и кеш этого не делают. Метаданные времени необязательны и не участвуют в согласовании.

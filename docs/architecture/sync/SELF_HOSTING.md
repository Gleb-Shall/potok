# Подключить свой Firebase

Без облака приложение хранит планы локально. Для синхронизации веб-разработки с другими устройствами:

1. Создать собственный проект Firebase и зарегистрировать Web-приложение.
2. Включить Authentication → Google, указать адрес поддержки и добавить адрес разработки в Authorized domains. Системный Google OAuth для Tauri требует отдельной интеграции и пока не реализован.
3. Создать Cloud Firestore Standard. Использовать production mode.
4. Установить `examples/firebase/firestore.rules` и `firestore.indexes.json` в своём проекте. Правила оставляют пользователю только его пространство и проверяют ревизии.
5. Скопировать объект firebaseConfig из настроек Web-приложения как JSON. В «Настройки → Своё облако» вставить объект, сохранить и после перезагрузки войти через Google.

Вместо формы можно создать игнорируемый git файл `.env.local`:

```dotenv
VITE_FIREBASE_CONFIG={"apiKey":"YOUR_BROWSER_KEY","authDomain":"YOUR_PROJECT.firebaseapp.com","projectId":"YOUR_PROJECT","appId":"YOUR_APP_ID"}
```

Управляемая сборка с этой переменной блокирует изменение проекта в интерфейсе. Перед сменой проекта в обычной установке нужно выйти из аккаунта. Смена проекта не переносит и не удаляет расписание: перенос выполняется отдельно через экспорт/импорт. Административный ключ service account не нужен и не должен попадать в конфигурацию клиента.

Конфигурация в браузере доступна посетителю, даже если пришла из переменных сборки. [Объяснение Firebase](https://firebase.google.com/docs/projects/api-keys). Правила и проверка пользователя обязательны.

Облачные сохранения используют транзакции и требуют сети. Локальный режим и кеш просмотра — отдельные механизмы; полноценная офлайн-запись с синхронизацией пока не реализована.

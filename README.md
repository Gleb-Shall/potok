# Уроки — расписание репетитора

Веб-приложение для базы учеников, недельного расписания и разовых переносов.

## Текущее состояние

Это локальная версия интерфейса. Вход и синхронизация через Firebase пока не подключены к интерфейсу.

- Реализована и проверена логика еженедельных занятий, разовых переносов, истории изменений, отмен и поиска пересечений.
- Добавлены заготовка подключения к Firebase и файл правил Firestore с разделением данных по аккаунтам. Правила ещё не опубликованы и не проверены на живом проекте.
- Демо-данные полностью вымышленные. Данные настоящих учеников в репозитории не хранятся.
- Работают недельное расписание, карточки учеников, добавление разовых и еженедельных уроков, разовые переносы, список ожидающих переноса, отметки о проведении и отмене.
- При переносе проверяются пересечения. Старое время остаётся бледной отметкой; следующая неделя не меняется.
- На узких экранах показывается выбранный день с переключателем недели. Перенос доступен кнопкой в карточке.
- Данные сохраняются в localStorage этого браузера. Есть резервное копирование в JSON и отмена последнего действия сразу после сохранения.
- CI/CD и публикация в Firebase пока не настроены.

## Локальная разработка

Нужны Node.js с поддержкой встроенного тестового раннера и Python 3. Внешние зависимости на данном этапе не требуются.

```sh
npm start
```

Открыть http://127.0.0.1:4173. Для будущей работы Google-входа этот домен необходимо разрешить в Firebase Authentication → Settings → Authorized domains.

Запуск проверок:

```sh
npm test
```

## Структура

```text
public/
  index.html          Страница приложения
  app.js              Интерфейс и пользовательские действия
  styles.css          Адаптивное оформление
  store.js            Локальное сохранение и разделение режимов
  domain.js           Даты, повторения, переносы и пересечения
  firebase-client.js  Подключение Firebase Authentication и Firestore
  demo.js             Синтетические данные для разработки
  icon.svg            Иконка приложения
tests/
  domain.test.js      Проверки логики расписания
firestore.rules       Правила доступа к данным
firebase.json         Настройки будущей публикации
.firebaserc           Идентификатор Firebase-проекта
```

Планируемые данные в Firestore разделяются по аккаунтам:

```text
users/{uid}/students/{studentId}
users/{uid}/series/{seriesId}
users/{uid}/lessons/{lessonId}
```

Повторяющиеся занятия вычисляются из постоянного расписания. В `lessons` сохраняются отдельные занятия и исключения: переносы, отмены и другие изменения конкретного урока.

## Разработка и публикация

1. Хранить исходный код и историю изменений в GitHub.
2. Разработать и проверить приложение локально.
3. Проверить Firebase-вход и правила доступа.
4. После готовности настроить CI/CD и размещение в Firebase Hosting.

Приложение впервые открывается с деморасписанием. Кнопка «Создать своё» переключает на пустое личное расписание, сохраняя демо отдельно. Переключение между режимами и скачивание резервной копии доступны в «Настройках».

Пока публикация не выполняется автоматически. Файлы Firebase здесь только подготавливают будущую настройку.

## Конфигурация и личные данные

В `public/firebase-client.js` находится клиентский `firebaseConfig`. Он доступен браузеру по назначению и не предоставляет административного доступа к проекту. Доступ к данным регулируется правилами Firestore.

Не добавлять в репозиторий выгрузки учеников, пароли, токены, приватные ключи или ключи сервисных аккаунтов. Firebase-конфигурацию не следует использовать для других платных Google API.

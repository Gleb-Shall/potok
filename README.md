# Поток — задачи и время

Название и оформление обновлены для универсального планировщика. Прежние ключи localStorage сохранены: переименование не затрагивает данные.

## План развития

[Направление продукта, мобильный интерфейс и будущие Canvas/WebGL-эффекты](docs/PRODUCT_PLAN.md). Документ разделяет зафиксированные решения и предложения для обсуждения.

## Аккаунт и публикация

- Google-вход доступен в шапке, боковом меню и настройках. Личное расписание синхронизируется между устройствами через Firestore.
- Демо остаётся локальным. Локальные записи не загружаются автоматически: в настройках есть отдельный перенос с подтверждением замены облачного расписания. JSON-копию с прежнего адреса можно скачать и восстановить на новом.
- Документ `users/{uid}/workspaces/main` доступен только владельцу. В памяти хранится текущая копия; после выхода облачные данные не показываются. Браузер сохраняет сессию входа.
- Сохранение подтверждается после транзакции. Проверка ревизии предотвращает перезапись изменений другого устройства; при конфликте редактор остаётся открытым. Без интернета облачная версия доступна для просмотра, изменения нужно сохранить после подключения.
- Для текущего небольшого планировщика данные сохраняются одним атомарным JSON-документом, до 900 КБ. Это позволяет согласованно сохранять переносы, удаления и шаблоны за одну запись. При росте объёма потребуется разделить хранение по коллекциям.
- Firebase project ID остаётся `tutor-s-lesson-schedule-b392f`: отображаемое имя — `Potok`. Переименование ID потребовало бы другого проекта. Имя веб-приложения — «Поток», репозиторий — `Gleb-Shall/potok`.

### CI/CD

`.github/workflows/firebase.yml` проверяет изменения для PR и `main`: логика, компоненты, правила базы в эмуляторе и production-сборка. После успешных проверок `main` автоматически публикуется на оба Firebase Hosting сайта.

GitHub использует Workload Identity Federation: только неизменяемый ID этого репозитория, его владелец и ветка `main`, без PR. Аккаунту `potok-deploy` выданы роль Firebase Hosting Admin и отдельное разрешение `serviceusage.services.get` для проверки состояния API перед публикацией. Доступа к расписаниям, правилам базы и включению сервисов у него нет. Постоянные ключи и пользовательские токены в GitHub не хранятся. Шаги Actions закреплены по SHA.

Правила Firestore CI проверяет, но не публикует: у служебного аккаунта нет доступа к данным и управлению правилами. Изменения правил публикуются владельцем проекта:

```sh
npx firebase deploy --only firestore:rules --project tutor-s-lesson-schedule-b392f
```

Клиентская конфигурация Firebase публичная по назначению; приватность обеспечивают Authentication и проверенные правила Firestore. SDK загружается отдельными модулями. Overrides в package.json фиксируют единое ядро Firebase и compat-ядро: без них зависимости SDK разрешаются в две несовместимые копии и вход/эмулятор не инициализируются.

### Последние изменения

- Карта выбора места и карта событий разворачиваются на всё окно. Escape сначала сворачивает карту выбора места.
- Геолокация запрашивается только по кнопке «Моё местоположение»; пользователь сам выдаёт разрешение в браузере.
- Начало, конец и длительность события пересчитываются в обе стороны. 00:00 означает полночь в конце выбранного дня.
- Полное удаление событий: один повтор или вся серия. Удалённый повтор не генерируется заново при перезагрузке.
- При удалении общей записи можно оставить события самостоятельными или удалить их вместе с записью.
- Удаление шаблона явно предупреждает об удалении его событий, повторов и переносов. Для сохранения событий можно использовать архивирование.
- Последнее удаление можно отменить через уведомление.

Добавлены проверки облачного формата, реальной инициализации SDK, аккаунта, конкурирующих правок, смены пользователя и правил доступа. Сценарии интерфейса проверяют также ранее реализованные функции. Геолокация проверена с имитацией успешного ответа и отказа; настоящая геопозиция пользователя не запрашивалась. В браузере проверены оформление, пересчёт времени и разворот/сворачивание карты.

Локальное приложение на Preact + Vite. Уроки с учениками, университетские пары, личные события и собственные типы карточек.

## Запуск

Нужны Node.js 24.12+ и npm. Для проверок правил базы — Java 21.

```sh
npm install
npm start
```

Открыть http://127.0.0.1:4173/.

```sh
npm run build
```

Готовая сборка находится в `dist/`. Основной сайт: https://potok-planner.web.app. Прежний адрес продолжает обслуживаться из той же сборки.

## Что реализовано

- Общие записи: ученики, люди, предметы, места, проекты и свои категории. События связываются с записью, а общие сведения хранятся отдельно от даты и времени.
- Готовые типы: урок, пара, личное мероприятие.
- Редактор названия, даты, времени, длительности, цвета, заметок и занятости.
- Конструктор типов: текст, длинный текст, число, дата, один вариант, несколько вариантов, флажок. Каждый вариант редактируется отдельной строкой. Настраиваются порядок, обязательность и показ на карточке.
- Скрытие использованных полей и архивирование типов без удаления существующих значений.
- Повтор каждые 1–12 недель с необязательной датой окончания.
- Изменение одного экземпляра либо выбранного и последующих событий.
- Неделя, две недели и месяц; компактные и раскрывающиеся карточки.
- Быстрый перенос: при перетаскивании выбирается только время, доступен переход к полному редактору.
- Выбор места поиском или точкой на карте, повторное использование мест, просмотр событий по меткам за выбранный период.
- Переносы с историей, отметкой старого времени и списком событий без новой даты.
- Проверка пересечений для событий, занимающих время.
- Отмена последнего изменения, сохранение в браузере, экспорт и восстановление JSON-копии.
- Раздельное хранение демо и личного расписания; миграция старого формата с сохранением исходной копии.

## Данные и подключение облака

Рабочие данные хранятся в localStorage этого браузера. Текущая схема: `version`, `students`, `records`, `types`, `series`, `events`, `revision`. Старые данные v2 без `records` открываются без потери учеников. При первом запуске новой версии прежние `lessons` преобразуются в общие события, а ключи хранения v1 сохраняются как исходная копия.

Firebase-вход, синхронизация, собственное HTTP API и CI/CD пока не подключены к интерфейсу. `firestore.rules` относится к предыдущей схеме и перед подключением облака требует обновления и проверки. Клиентская конфигурация Firebase предназначена для браузера; приватные ключи и личные данные в репозиторий не добавляются.

## Карта и поиск мест

Современная векторная карта MapLibre GL JS с подложкой OpenFreeMap. Карта и её рабочий модуль загружаются только при открытии, основной экран их заранее не скачивает. Масштабирование работает колёсиком, трекпадом и жестами без Ctrl. Метки можно передвигать. Храним обычные координаты, название и адрес, независимо от поставщика карты.

Поиск Photon показывает подсказки через 350 мс после ввода минимум двух символов, отменяет старый запрос при изменении строки и кэширует результаты. Работают стрелки, Enter и Escape. Поиск предпочитает Санкт-Петербург, не запрашивая местоположение устройства. Внешнему сервису передаётся строка поиска и, при определении адреса, координаты выбранной метки; имена учеников и заметки не отправляются.

OpenFreeMap не требует регистрации, ключа и платёжного аккаунта. Публичный Photon предназначен для умеренного использования и не гарантирует доступность. Настройки `VITE_MAP_STYLE_URL`, `VITE_MAP_REVERSE_URL` и `VITE_MAP_SEARCH_URL` позволяют менять сервисы; поисковый сервер должен поддерживать Photon API. При отказе поиска можно выбрать точку на карте. После нажатия и перемещения метки автоматически определяется адрес (обратное геокодирование). Координаты остаются точными координатами нажатия; если адреса нет или сервис не ответил за 6 секунд, доступно сохранение координат. Введённое вручную название сохраняется при получении адреса.

Документация: [OpenFreeMap](https://openfreemap.org/quick_start/), [публичный сервер Photon](https://github.com/komoot/photon#demo-server).

## Пробное подключение Apple Maps

Сохранённый предрелиз: [v0.2.0-alpha.1](https://github.com/Gleb-Shall/tutor-schedule/releases/tag/v0.2.0-alpha.1). Пробное подключение Apple Maps ведётся отдельно в ветке `feat/apple-maps`.

Добавлены официальный загрузчик Apple MapKit JS 6, карта, метки, жесты, поиск Apple с автодополнением и определением координат выбранной подсказки. В окне выбора места и на карте событий можно переключаться между Apple Maps и OpenFreeMap. Выбор сохраняется на этом устройстве. Без токена Apple Maps показывает причину недоступности; OpenFreeMap продолжает работать.

Для настоящей загрузки карты нужен **браузерный Maps Token типа MapKit JS**. Создание токена требует доступа к Apple Developer Program (личное участие обычно стоит $99 в год) либо команде участника программы; обычного Apple ID недостаточно. [Условия участия Apple](https://developer.apple.com/programs/whats-included/). Приватный ключ `.p8` не нужен и не должен попадать в проект.

1. Войти в [Apple Developer Account](https://developer.apple.com/account).
2. Открыть Certificates, Identifiers & Profiles → Services → Maps → Configure → Tokens → +.
3. Выбрать тип MapKit JS, ограничение Domain и добавить домены разработки `127.0.0.1` и `localhost`. Для опубликованного сайта позднее добавить его домен.
4. Создать токен и сохранить его локально в `.env.local`:

```dotenv
VITE_APPLE_MAPS_TOKEN=ваш_браузерный_Maps_Token
VITE_MAP_PROVIDER=apple
```

5. Перезапустить `npm start`, обновить страницу и выбрать Apple Maps в переключателе источника карты.

`.env.local` игнорируется Git. Клиентский токен попадёт в браузерную сборку, поэтому его нужно ограничить доменами в Apple Developer. Токен создаётся и регулируется в аккаунте Apple пользователя; без него невозможно проверить настоящий ответ Apple Maps.

Официальная инструкция: [Creating a Maps token](https://developer.apple.com/documentation/mapkitjs/creating-a-maps-token), [MapKit JS 6](https://webkit.org/blog/18027/discover-mapkit-js-6-rebuilt-for-todays-web-developer/).

```sh
npm test
npm run test:ui

```

34 проверки логики: даты, разовые переносы и история, сохранение повторов, ожидание времени, пересечения, общие записи, множественный выбор, место и сохранение данных. 28 проверок компонентов и подключения в jsdom: переключение периода, раскрытие карточек, перетаскивание и сохранение, связанные записи, конструктор вариантов, переход к полному редактору, выбор места, вложенное окно карты, отказ поиска, открытие события по метке. Дополнительно проверены отсутствие Maps Token, жесты Apple Maps, выбор подсказок и отмена запросов Apple. В jsdom SDK карт подменены: эта среда не имеет GPU и тестового токена Apple.

В реальном браузере дополнительно проверены загрузка векторной карты, реальные подсказки по запросу общественного места, выбор с клавиатуры и масштабирование прокруткой в обе стороны. Полный прогон всех функций на телефоне и разных браузерах ещё не выполнен.

Дополнительно проверены обратное геокодирование, отсутствие адреса, отказ сервиса, кэширование, сохранение точных координат и пользовательского названия. В реальном браузере по нажатию на карту получен адрес Невского проспекта.

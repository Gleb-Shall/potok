# Поток

Календарь, который можно настроить под себя: события, связанные записи, собственные шаблоны карточек и переносы с сохранением истории.

Открытый репозиторий содержит интерфейс, логику и исходники приложения Tauri. По умолчанию данные сохраняются на устройстве, аккаунт не требуется. Своя авторизация и хранилище подключаются адаптером; Firebase — один из необязательных вариантов. Настройки и публикация нашего сайта находятся в отдельном закрытом репозитории.

## Разработка в браузере

Нужны Node.js 24.12+ и npm.

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173/. Локальное приложение открывается сразу, без аккаунта. Браузер остаётся основным способом разработки интерфейса.

## Приложение Tauri

```sh
npm run desktop:dev
npm run desktop:build
```

Готовые `.exe` для Windows x64 и `.dmg` для Mac (отдельно Apple Silicon и Intel) публикуются в [Releases](https://github.com/Gleb-Shall/potok/releases). Это локальная открытая версия, без встроенного облака владельца проекта. Предварительные сборки пока без сертификатов доверенного издателя; особенности первого запуска указаны в релизе.

Для сборки из исходников нужны Rust и системные инструменты: [официальные требования Tauri](https://v2.tauri.app/start/prerequisites/). Системный Google OAuth и SQLite пока не реализованы. Подробнее — [устройство настольной версии](docs/architecture/local-app/README.md).

## Возможности

- День, неделя по времени, доска и месяц.
- Быстрое перемещение карточки и удержание с выбором даты из месяца.
- Повторы, разовый перенос, очередь ожидания и история.
- Связанные записи и настраиваемые поля шаблонов.
- Именованные ссылки, PNG-фоны, карта мест событий.
- Напоминания о конкретных переносах.

## Своё облако

Сборка передаёт свой провайдер в `<App provider={provider}/>`: способ входа и облачный backend выбирает владелец сборки. Наличие Firebase-конфига не включает его автоматически. В обычной локальной версии кнопки входа нет.

[Контракт своего адаптера](docs/architecture/sync/ADAPTERS.md) · [Пример подключения Firebase](docs/architecture/sync/SELF_HOSTING.md). Перед каждой облачной записью календарь читает серверную версию и затем выполняет атомарное сохранение с проверкой ревизии. При конфликте черновик сохраняется в редакторе. Для облачной записи нужна сеть; локальный режим независим от неё.

## Проверки

```sh
npm test
npm run test:ui
npm run build
```

Для проверки правил Firestore нужны Java 21 и команда `npm run test:rules`. Проверки используют демонстрационный проект, не рабочую базу.

## Устройство проекта

- `src/App.jsx` — рабочее пространство и общий интерфейс.
- `src/components/` — календарь, карточки, редакторы и настройки.
- `src/lib/` — модель событий, хранение и подключение облака.
- `src/hooks/` — состояние пространства и жесты.
- `src-tauri/` — системная оболочка приложения.
- `examples/firebase/` — пример правил для своего Firebase.
- `tests/` — проверки поведения и модели.
